Why this file exists
---------------------
Three failures, all silent, all in the same week:

1. 2026-08-16 — a push landed in the wrong repo. The build was correct and the
   record said shipped, but the files went to steamteams-cc-ops instead of
   steamteams-cc-portal, so nothing reached the live site.

2. 2026-08-17 (earlier) — a correct push sat undeployed. Vercel's GitHub
   webhook did not fire, production stayed on the previous build, and
   x-vercel-cache: HIT with a stale last-modified was the only tell.

3. 2026-08-17 (this failure) — the check adopted to catch the first two was
   itself broken for about a day and nobody noticed, because nobody fetched
   it. It lived at /version.txt, a root-level non-HTML file. This deployment
   does not serve root-level non-HTML files at all — /README.md, /robots.txt
   and /vercel.json all return the same 79-byte 404, and always have.
   /README.md has been committed since the initial commit and was never once
   reachable. A wave following the old rule literally would have declared
   every correct deploy a failure. Root cause: a safeguard was written,
   committed, pushed, and documented — and never once exercised against the
   live system in anger.

This file replaces /version.txt as the deploy check. W3.9h deployed two
candidates at once rather than assuming the cause — this file at the repo
root, and /assets/version.txt — and fetched both live. Both returned 200:
root-level exclusion applies to non-HTML files specifically, not to
everything outside /assets/, so a root .html file and an /assets/*.txt file
both serve. This one was kept because it matches every real page in this
repo (root-level .html) and does not sit inside /assets/, a path more likely
to pick up long-lived cache headers in a future optimization pass — the
wrong property for a file that must read as fresh on every fetch. The
/assets/version.txt candidate was deleted in the same commit that added this
paragraph.

After any push, fetch this file and confirm the wave line matches what was
just pushed. If it does not, the deploy did not land, whatever the commit
history says.
